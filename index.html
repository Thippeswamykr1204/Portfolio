00 / APPROACH

How I build

Engineering principles applied to every project below

I learn by shipping. Every project starts as a working increment, gets hardened with tests and validation, then gets iterated until it's something I'd defend in a system-design interview — not something I'd hide from one.

01
Ship the thin slice first
I build the smallest version that works end to end — UI to database — before adding features. It surfaces integration problems on day one instead of week three.
02
Harden before I call it done
Zod validation at every boundary, JWT auth on protected routes, Jest/Supertest coverage on the paths that matter. PulseQ and the Library Management API both carry 55+ integration tests.
03
Debug the root cause, not the symptom
CORS misconfigurations, MongoDB transaction race conditions, replica-set testing quirks — I've traced each of these to source rather than patching around them.
